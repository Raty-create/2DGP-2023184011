## 1. 개요

`sonic-sprite.png` 스프라이트 시트에 담긴 모든 애니메이션을 순서대로 재생해
확인할 수 있는 **애니메이션 뷰어**를 만든다.

pico2d(Python + PySDL)로 구현하며, 한 프레임씩 순차 재생하는 단순한
상태 기계만 사용한다. 게임 루프, 입력 처리, 상태 전이 외의 것은 넣지 않는다.

---

## 2. 목표 / 비목표

### 2.1 목표

- G1. 스프라이트 시트의 모든 애니메이션(10개 액션, 총 76프레임)을 빠짐없이 재생한다.
- G2. 원본 해상도의 **4배**로 확대해 화면에 그린다.
- G3. 액션마다 **5회 반복 → 1초 정지 → 다음 액션**으로 전환한다.
- G4. 전체 목록은 **종료 이벤트가 발생하기까지 무한 반복**한다.
- G5. 동작이 지나치게 빠르거나 느리지 않은 **자연스러운 재생 속도**를 유지한다.
- G6. 코드를 한 번에 쓰지 않고, 의미 있는 커밋 **20개 이상**으로 나눠 작성한다.
- G7. 커밋 메시지는 **무조건 한글**로 작성한다. (NFR-7, §10 규칙 참조)

### 2.2 비목표 (Out of Scope)

- 사용자 조작(프레임 이동, 슬라이더, 일시정지 키 등) — 없음
- 음향, 파티클, 물리, 충돌 — 없음
- 시트 자동 분석(프레임 자동 탐지) — 없음. 프레임 좌표는 **소스에 하드코딩**한다.
- 다중 애니메이션 동시 재생 — 없음. 한 번에 액션 1개만 재생한다.
- 애니메이션 편집/추가 기능 — 없음

## 3. 사용자 시나리오

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 콘솔에 스프라이트 시트 크기와 액션별 프레임 수가 출력된다.
3. 캔버스 중앙에 첫 액션이 4배 크기로 재생된다.
4. 액션이 끝나면 마지막 프레임에서 1초간 멈춘다.
5. 다음 액션이 이어서 재생되고, 이 과정이 목록 끝까지 반복된다.
6. 사용자가 `ESC` 또는 창 닫기를 누르면 정상 종료한다.

## 5. 입력 데이터 — 스프라이트 시트 규격

`sonic-sprite.png`에 대해 **픽셀 분석으로 측정한 값**이다. 추측이 아니다.

### 5.1 이미지 속성

| 속성             | 값                            | 비고 |
| ---------------- | ----------------------------- | ---- |
| 크기             | 399 × 525 px                 |      |
| 색상 모드        | RGBA (PNG color type 6, 8bit) |      |
| 배경             | 완전 투명 (모서리 알파 = 0)   |      |
| 프레임 경계 구분 | 알파 채널만으로 가능          |      |

> **설계 영향:** LEC08의 `animation_viewer.py`는 알파가 없는 RGB 시트라
> 프레임 사각형의 배경색이 화면에 드러나도록 캔버스를 덮는 처리가 필요했다
> (`SHEET_BACKGROUND`). sonic 시트는 투명 배경이므로 **그 처리가 필요 없다.**
> `clear_canvas()` 만으로 충분하며, 시트에 포함된 배경색을 덮으면 오히려
> 프레임 좌표 오차를 눈으로 확인할 수 없게 된다.

### 5.2 시트 레이아웃

시트는 **균일 격자가 아닌 밀집 배치**다. 행마다 프레임 높이(27~45px)와
프레임 개수(4~12개)가 모두 다르며, 좌우 간격도 일정하지 않다.
따라서 `(열, 행)` 기반의 단순 격자 계산으로는 프레임을 얻을 수 없고,
**행별 프레임 사각형을 직접 나열**해야 한다.

전체 시트는 세로로 12개 밴드(band)로 나뉜다.

| 밴드 | y 범위     | 높이 | 프레임 수 | 분류                    |
| ---- | ---------- | ---- | --------- | ----------------------- |
| 0    | 1 – 32    | 32   | —        | 타이틀 로고 (제외)      |
| 1    | 39 – 77   | 39   | 11        | 액션 1                  |
| 2    | 79 – 117  | 39   | 12        | 액션 2                  |
| 3    | 121 – 163 | 43   | 6         | 액션 3                  |
| 4    | 167 – 199 | 33   | 9         | 액션 4                  |
| 5    | 206 – 232 | 27   | 6         | 액션 5                  |
| 6    | 238 – 273 | 36   | 6         | 액션 6                  |
| 7    | 283 – 317 | 35   | 6         | 액션 7                  |
| 8    | 326 – 370 | 45   | 8         | 액션 8                  |
| 9    | 377 – 416 | 40   | 8         | 액션 9                  |
| 10   | 426 – 468 | 43   | 4         | 액션 10                 |
| 11   | 472 – 524 | 53   | —        | 푸터 캡션 + 로고 (제외) |

- **제외 대상:** 밴드 0, 밴드 11. 둘 다 텍스트·로고이며 애니메이션이 아니다.
  **액션 목록에 넣지 않는다** ([§12-D2](#12-결정-기록)).
- **재생 대상:** 밴드 1~ 10 → 액션 10개, 프레임 합계 **76개**.
- 밴드 11에는 캡션 오른쪽에 27×39, 23×39 크기의 두 덩어리가 있으나
  텍스트 로고로 확정했다. 액션으로 편입하지 않는다.

### 5.3 액션 정의 (프레임 사각형 테이블)

`Frame(left, bottom, width, height)` — `width`, `height`는 잘라낼 크기다.

`left`은 시트 왼쪽에서 센 x좌표다. `bottom`은 시트 **아래쪽 끝에서 위로 센
y좌표**이며, 왼쪽 위 기준 값이 **아니다.** `clip_draw`가
`src_rect = (left, 시트높이 - bottom - height)`로 사각형을 잘라내기 때문이다.

> **좌표계 주의 (1.1 개정):** 본 문서 초판은 `bottom`을 좌상단 기준으로 적었다.
> 그러나 `clip_draw(left, bottom, ...)`는 `self.h - bottom - height`로 **뺀다.**
> 좌상단 기준 값을 그대로 넘기면 다른 행을 잘라 엉뚱한 그림이 그려진다.
> 아래 표의 `bottom`은 시트 높이 525에서 `525 - (행 끝 y)`로 환산한 값이다.
> (예: 밴드 1이 39~77행이면 `525 - 77 = 448`, 경계 포함 여부에 따라 447)

**액션 내 모든 프레임의 `bottom`을 같은 값으로 통일**했다. 프레임마다 실제
높이가 다르므로, 상단을 동일하게 맞추면 캐릭터가 위아래로 흔들린다. `bottom`을
통일하면 발이 붙는 바닥선이 항상 맞아 [§7.5](#fr-5-4배-확대--바닥선-정렬)의
정렬 요구를 프레임 데이터만으로 만족시킬 수 있다. 단 `Death`는 넘어지는 동작이라
앞 2프레임(56)과 뒤 2프레임(59)의 차이를 그대로 둔다.

> **액션 이름 규칙:** 아래 이름은 시트에 원본 동작명이 표기되어 있지 않아
> 프로젝트에서 붙인 가칭이다. 처음에는 추측 성격이 있었으나, 가칭을 그대로
> 정식 명칭으로 확정했다 ([§12-D3](#12-결정-기록)). 구현·콘솔 출력·UI 표기에
> 아래 이름을 그대로 쓴다.

## 6. 상태 모델

액션마다 독립적인 재생 상태를 하나씩 둔다. 현재 재생 중인 액션의 상태만
전진시키고, 나머지는 건드리지 않는다.

```python
{
    "frame":         0,     # 현재 프레임 인덱스
    "frame_elapsed": 0.0,   # 현재 프레임이 표시된 시간
    "repeat":        0,     # 완료한 사이클 수
    "done":          False, # 5회 반복 + 정지를 모두 마쳤는지
    "pause_elapsed": 0.0,   # 정지 구간 경과 시간
    "last_time":     0.0,   # 마지막 갱신 시각
}
```

전역 변수:

| 이름                 | 역할                                           |
| -------------------- | ---------------------------------------------- |
| `current_action`   | 지금 재생 중인 액션의 인덱스                   |
| `current_finished` | 현재 액션의 재생을 끝내고 다음으로 넘어갈 신호 |

## 7. 기능 요구사항

### FR-1. 캔버스 및 이미지 로딩

- FR-1.1 캔버스는 **800 × 600**으로 연다.
- FR-1.2 `sonic-sprite.png`를 `load_image()`로 불러온다.
- FR-1.3 시트는 알파가 있는 투명 배경이므로, 매 프레임 `clear_canvas()`만
  호출한다. LEC08의 `SHEET_BACKGROUND` 덮어쓰기 처리는 **도입하지 않는다.**
- FR-1.4 로드 직후 시트 크기와 액션별 프레임 수를 콘솔에 출력한다.

### FR-2. 프레임 정의

- FR-2.1 `Frame = namedtuple("Frame", "left bottom width height")` 를 사용한다.
- FR-2.2 `§5.3`의 액션 10개를 순서대로 정의하고, `SPRITE` 목록으로 묶는다.

  ```python
  SPRITE = [
      ("Idle", IDLE_FRAMES),
      ("Walk", WALK_FRAMES),
      # ... 총 10개
      ("Death", DEATH_FRAMES),
  ]
  ```
- FR-2.3 프레임 사각형은 소스에 하드코딩한다. 시트 로드 시 자동 탐지하지 않는다.
- FR-2.4 액션 추가·삭제 시 `SPRITE` 목록만 고치면 나머지 재생 로직은
  수정 없이 동작해야 한다.

### FR-3. 재생 진행

- FR-3.1 한 프레임 표시 시간은 `FRAME_DURATION`(기본 0.08초)이다.
- FR-3.2 경과 시간은 `get_time()` 차이로 계산한다. 프레임 카운터로 프레임 수를
  세지 않는다(타이밍이 프레임레이트에 종속되므로).
- FR-3.3 한 사이클이 끝나면 마지막 프레임에서 처음으로 되돌아간다.
- FR-3.4 액션을 **5회 반복**하면 `done = True` 로 전환하고, 마지막 프레임을
  화면에 유지한 채 **1초 동안 정지**한다.
- FR-3.5 정지가 끝나면 `current_finished = True` 로 신호를 보내고, 다음 프레임의
  `select_next_action()`이 이 신호를 받아 액션을 전환한다.
- FR-3.6 액션 전환 시 대상 액션 상태를 `frame = 0`, `repeat = 0`,
  `last_time = get_time()` 으로 초기화한다.
- FR-3.7 전환은 `current_action = (current_action + 1) % len(SPRITE)` 로 처리해
  **마지막 액션 다음에 첫 액션으로 돌아간다.** 전체 목록이 무한 반복된다.

### FR-4. 재생 속도

- FR-4.1 속도는 **프레임 수가 다른 액션이라도 사이클 길이가 비슷하도록** 맞춘다.
  기준 사이클 길이는 **0.5 ~ 1.0초** 범위로 본다.
- FR-4.2 전역 기본값 `FRAME_DURATION = 0.08`(12.5fps)으로 시작한다.
  4프레임 액션은 0.32초, 12프레임 액션은 0.96초가 되어 위 범위 안에 든다.
- FR-4.3 육안 확인으로 너무 빠르거나 느린 액션이 있으면 액션별로
  `FRAME_DURATION`을 다르게 지정할 수 있게 한다(전역값 교체 금지).
- FR-4.4 `FRAME_DURATION`이 0 이하가 되면 재생이 멈추므로 상수 검증 코드를 둔다.

### FR-5. 4배 확대 + 바닥선 정렬

- FR-5.1 `CHARACTER_SCALE = 4` 로 확대해 그린다.
  최대 프레임 높이 45px → 화면에서 180px.
- FR-5.2 잘라내는 크기(`frame.width`/`frame.height`)와 화면 표시 크기
  (`* CHARACTER_SCALE`)를 분리한다.
- FR-5.3 캐릭터는 캔버스 가로 중앙에 정렬한다.
- FR-5.4 세로 위치는 **프레임 중앙이 아니라 프레임의 아래쪽 끝**을 기준으로
  계산해, 발이 닿는 바닥선이 액션 내내 고정되게 한다. 프레임 높이가 다른
  액션(5: 27px, 8: 45px 등)에서 캐릭터가 뜨거나 파묻히는 것을 막는다.
- FR-5.5 `GROUND_Y` 상수로 기준선을 한 곳에 정의한다. 최대 표시 높이 180px를
  감안해 `GROUND_Y = 380` 을 기본값으로 한다.

### FR-6. 진행 표시 UI

- FR-6.1 화면에 현재 액션의 반복 횟수를 5칸 인디케이터로 표시한다.
- FR-6.2 반복을 마친 칸은 채우고, 아직 남은 칸은 비운다.
- FR-6.3 정지 구간(5회 반복 완료)에는 5칸을 모두 채워 정지 중임을 알린다.
- FR-6.4 현재 액션 이름을 화면에 함께 표시한다.
- FR-6.5 인디케이터와 액션 이름은 캐릭터와 겹치지 않는 위치에 둔다.

### FR-7. 종료 이벤트

- FR-7.1 `SDL_QUIT` 이벤트 또는 `ESC` 키(`SDLK_ESCAPE`) 입력 시 실행을 끝낸다.
- FR-7.2 종료 시 `close_canvas()`를 호출해 창을 정상 종료한다.
- FR-7.3 PRE-PRD의 "종료 이벤트가 있을 때까지 무한 반복"은 **이벤트 루프가
  종료 이벤트(창 닫기 / ESC)를 받을 때까지 전체 액션 목록을 계속 반복**한다는
  뜻으로 해석한다. 프로그램이 스스로 종료하는 시점은 없다.

### D5 후속 — 구현 후 확인할 항목

`FRAME_DURATION = 0.08`은 LEC08에서 가져온 기준값이며 sonic 시트에 맞춘 검증은
아직 없다. 다음은 **문서 결정을 기다리는 항목이 아니라, 구현 마지막 단계에서
수행하는 확인 작업**이다. (§10 Phase 5의 커밋 24~25에 해당한다.)

- [ ] 4프레임 `Death`(사이클 0.32초)가 성급하게 느껴지지 않는가
- [ ] 12프레임 `Walk`(사이클 0.96초)가 느리게 느껴지지 않는가
- [x] 특정 액션만 어색하면 그 액션에만 `FRAME_DURATION`을 다르게 지정할 수 있다
      (FR-4.3). `ACTION_FRAME_DURATION`에 액션 이름을 적으면 되고, 전역값
      `FRAME_DURATION`은 바뀌지 않는다.
- [x] `FRAME_DURATION`이 0 이하이면 어느 값이 문제인지 알려 주고 멈춘다 (FR-4.4).

> **육안 확인은 아직 하지 않았다.** `FRAME_DURATION = 0.08`은 LEC08에서 가져온
> 기준값일 뿐 sonic 시트에 맞춰 눈으로 확인한 적이 없다. 위 두 항목은
> 사용자가 직접 실행해 보고 결정해야 한다. 필요한 경우
> `ACTION_FRAME_DURATION = {"Death": 0.12}`처럼 해당 액션만 지정하면 된다.
